A Carvel package for [Contour](https://projectcontour.io), a high performance gateway and ingress controller for Kubernetes based on Envoy.

## ✨&nbsp; What's Included

* **Gateway API**. A default Gateway serving HTTP, and HTTPS for your domain with a certificate from cert-manager.
* **Ingress and HTTPProxy**. The `contour` IngressClass and the Contour `HTTPProxy` API, served by the same Envoy instances as the Gateway.
* **High availability**. Contour and Envoy run 2 replicas each, protected by PodDisruptionBudgets. Envoy is exposed via a `LoadBalancer` Service.
* **Observability**. Structured logs, Prometheus metrics, and OpenTelemetry traces.
* **TLS**. TLS 1.3 by default, and mutual TLS between Contour and Envoy with certificates generated by Contour or issued by cert-manager.
* **Security**. The workloads comply with the `restricted` [Pod Security Standard](https://kubernetes.io/docs/concepts/security/pod-security-standards/), enforced on the package namespace.
* **Local development**. Tested presets for running on [kind and k3d](docs/local.md).

## 🚀&nbsp; Getting Started

### Prerequisites

* Kubernetes 1.35+
* Carvel [`kctrl`](https://carvel.dev/kapp-controller/docs/latest/install/#installing-kapp-controller-cli-kctrl) CLI.
* Carvel [kapp-controller](https://carvel.dev/kapp-controller) deployed in your Kubernetes cluster. You can install it with Carvel [`kapp`](https://carvel.dev/kapp/docs/latest/install) (recommended choice) or `kubectl`.

```shell
kapp deploy -a kapp-controller -y \
  -f https://github.com/carvel-dev/kapp-controller/releases/latest/download/release.yml
```

### Dependencies

Contour has no required dependencies. [cert-manager](https://github.com/kadras-io/package-for-cert-manager) is needed to serve HTTPS on the Gateway (`gateway.tls.issuer`) and to issue the certificates between Contour and Envoy (`tls.internal.provider: cert-manager`). You can install it from the [Kadras package repository](https://github.com/kadras-io/kadras-packages).

### Installation

Add the Kadras [package repository](https://github.com/kadras-io/kadras-packages) to your Kubernetes cluster:

```shell
kctrl package repository add -r kadras-packages \
  --url ghcr.io/kadras-io/kadras-packages \
  -n kadras-system --create-namespace
```

<details><summary>Installation without package repository</summary>
The recommended way of installing the Contour package is via the Kadras <a href="https://github.com/kadras-io/kadras-packages">package repository</a>. If you prefer not using the repository, you can add the package definition directly using <a href="https://carvel.dev/kapp/docs/latest/install"><code>kapp</code></a> or <code>kubectl</code>.

```shell
kubectl create namespace kadras-system
kapp deploy -a contour-package -n kadras-system -y \
  -f https://github.com/kadras-io/package-for-contour/releases/latest/download/metadata.yml \
  -f https://github.com/kadras-io/package-for-contour/releases/latest/download/package.yml
```
</details>

Install the Contour package:

```shell
kctrl package install -i contour \
  -p contour.packages.kadras.io \
  -v ${VERSION} \
  -n kadras-system
```

> **Note**
> You can find the `${VERSION}` value by retrieving the list of package versions available in the Kadras package repository installed on your cluster.
>
> ```shell
> kctrl package available list -p contour.packages.kadras.io -n kadras-system
> ```

Verify the installed packages and their status:

```shell
kctrl package installed list -n kadras-system
```

### Try It Out

Deploy an application and route traffic to it through the default Gateway:

```shell
kubectl create deployment hello --image=ghcr.io/knative/helloworld-go:latest --port=8080
kubectl expose deployment hello --port=80 --target-port=8080

kubectl apply -f - <<EOF
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: hello
spec:
  parentRefs:
    - name: contour
      namespace: projectcontour
      sectionName: http
  hostnames:
    - hello.example.com
  rules:
    - backendRefs:
        - name: hello
          port: 80
EOF
```

Send a request to the Envoy Service. On a [local cluster](docs/local.md), use `localhost` as the address.

```shell
ADDRESS=$(kubectl get service envoy -n projectcontour -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
curl -H "Host: hello.example.com" http://$ADDRESS
```

## 🎯&nbsp; Configuration

The Contour package can be customized via a `values.yml` file.

```yaml
gateway:
  domain: example.com
  tls:
    issuer: kadras-ca-issuer
observability:
  logging:
    format: json
tls:
  internal:
    provider: cert-manager
```

Reference the `values.yml` file from the `kctrl` command when installing or upgrading the package.

```shell
kctrl package install -i contour \
  -p contour.packages.kadras.io \
  -v ${VERSION} \
  -n kadras-system \
  --values-file values.yml
```

Anything not covered by the values can be customized via the Contour configuration file or ytt overlays, as described in [docs/configuration.md](docs/configuration.md).

### Values

The Contour package has the following configurable properties.

<details><summary>Configurable properties</summary>

<!-- values-table:start -->

| Config | Default | Description |
|--------|---------|-------------|
| `namespace` | `"projectcontour"` | The namespace in which to deploy Contour and Envoy. |
| `gateway.enabled` | `true` | Whether to create the `contour` GatewayClass and the default Gateway, and configure Contour to serve it. |
| `gateway.install_crds` | `true` | Whether to install the CRDs from the experimental channel of the Gateway API, required by the Gateway. Set it to `false` if the Gateway API CRDs are already managed by something else in the cluster. |
| `gateway.name` | `"contour"` | The name of the Gateway, created in the package namespace. |
| `gateway.allowed_routes` | `"All"` | The namespaces from which routes can attach to the Gateway. `All` allows any namespace, `Same` only the package namespace. |
| `gateway.domain` | `""` | The domain served over HTTPS by the Gateway via a wildcard certificate (`*.<domain>`). It requires `tls.issuer`. |
| `gateway.tls.issuer` | `""` | The name of the cert-manager ClusterIssuer that issues the wildcard certificate for `domain`. For ACME issuers, wildcard certificates require a DNS-01 challenge. |
| `gateway.tls.http_redirect` | `true` | Whether to redirect HTTP requests for `*.<domain>` to HTTPS. |
| `contour.replicas` | `2` | The number of Contour replicas. Additional replicas are standby via leader election. With more than 1 replica, a PodDisruptionBudget is created. |
| `contour.config` | `{}` | Contour configuration, merged on top of the one computed by the package. See https://projectcontour.io/docs/latest/configuration/#configuration-file. |
| `envoy.kind` | `"Deployment"` | The Kubernetes workload Envoy runs as. |
| `envoy.replicas` | `2` | The number of Envoy replicas when `kind` is `Deployment`. With more than 1 replica, a PodDisruptionBudget is created. |
| `envoy.termination_grace_period_seconds` | `300` | How long to wait, in seconds, for Envoy to drain open connections before terminating. |
| `envoy.service.type` | `"LoadBalancer"` | The type of the Service. |
| `envoy.service.external_traffic_policy` | `"Local"` | The external traffic policy of the Service, when `type` is `LoadBalancer` or `NodePort`. `Local` preserves the client source IP. |
| `envoy.service.annotations` | `{}` | Annotations for the Service, for example to configure the load balancer implementation. |
| `envoy.service.node_ports.http` | `0` | The node port for HTTP traffic. |
| `envoy.service.node_ports.https` | `0` | The node port for HTTPS traffic. |
| `envoy.host_ports.enabled` | `false` | Whether to expose Envoy on host ports. |
| `envoy.host_ports.http` | `80` | The host port for HTTP traffic. |
| `envoy.host_ports.https` | `443` | The host port for HTTPS traffic. |
| `envoy.proxy_protocol` | `false` | Whether Envoy expects the PROXY protocol on all its listeners, as sent by some load balancers to preserve the client source IP. |
| `tls.internal.provider` | `"certgen"` | How the certificates are provisioned. `certgen` generates them with a Job at every installation and upgrade, and doesn't renew them in between. `cert-manager` issues and renews them via cert-manager, which must be installed in the cluster. |
| `tls.internal.duration` | `"8760h"` | How long the certificates are valid, in hours. |
| `tls.internal.renew_before` | `"360h"` | How long before expiry the certificates are renewed, in hours. Only for the `cert-manager` provider. |
| `observability.logging.level` | `"info"` | The log level for Contour and Envoy. Contour only distinguishes between `debug` and the rest. |
| `observability.logging.format` | `"text"` | The format of the Contour logs and of the Envoy access logs. |
| `observability.metrics.enabled` | `true` | Whether to annotate the Contour and Envoy Pods for Prometheus scraping. |
| `observability.tracing.enabled` | `false` | Whether to export traces from Envoy. |
| `observability.tracing.endpoint` | `""` | The OTLP/gRPC endpoint of an in-cluster OpenTelemetry collector, in the form `[http://]<service>.<namespace>[.svc[.cluster.local]]:<port>`. |
| `observability.tracing.sampling_rate` | `1` | The fraction of requests to trace, from 0 (never) to 1 (always). |

<!-- values-table:end -->

</details>

## 🛠️&nbsp; Development

The development environment is defined with [devenv](https://devenv.sh). Enter it with `devenv shell`, or automatically with [direnv](https://direnv.net) after running `direnv allow`. Run `task --list` to see all the available tasks.

```shell
# Run the unit tests, which render the package and check the result without a cluster.
task test:config

# Create a local kind cluster and run the integration tests on it.
task cluster:setup
task test:integration

# Deploy the package from the local sources to the current cluster.
task dev

# Update the table of configurable values in this README after changing the values schema.
task docs:values
```

The unit tests are described in [test/unit/README.md](test/unit/README.md).
