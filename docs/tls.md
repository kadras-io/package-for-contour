# TLS

## TLS version

Envoy only accepts TLS 1.3 connections, on every listener. If some clients only support TLS 1.2, lower the minimum version via the Contour configuration:

```yaml
contour:
  config:
    tls:
      minimum-protocol-version: "1.2"
```

## Certificates for your applications

The certificates served to clients are configured per resource:

* for HTTPRoutes, on the Gateway (see [gateway-api.md](gateway-api.md#https-for-a-domain));
* for HTTPProxy, via [`spec.virtualhost.tls`](https://projectcontour.io/docs/latest/config/tls-termination/);
* for Ingress, via `spec.tls`.

Use the [cert-manager package](https://github.com/kadras-io/package-for-cert-manager) to issue and renew them. See [Contour with cert-manager](https://projectcontour.io/docs/latest/guides/cert-manager/).

## Internal certificates

Contour sends routing configuration to Envoy over a gRPC connection secured by mutual TLS: Contour presents the certificate in the `contourcert` Secret, Envoy the one in the `envoycert` Secret, both signed by the same CA. These certificates have nothing to do with the traffic served to clients.

By default, they are generated by the `contour-certgen` Job, which runs at every installation and upgrade of the package, and when the `tls.internal` values change.

> [!WARNING]
> Nothing renews the certificates generated by the Job. If the package isn't upgraded within `duration` (one year by default), they expire and Envoy stops receiving configuration from Contour: existing routes keep working, but changes are no longer applied, and new Envoy pods can't serve traffic.

To renew them manually, delete the Job. kapp-controller recreates it at the next reconciliation of the package, and it overwrites the certificates. Then restart Contour and Envoy to load them (use `daemonset/envoy` if Envoy runs as a DaemonSet).

```shell
kubectl delete job -n projectcontour -l app=contour-certgen
kctrl package installed kick -i contour -n kadras-system
kubectl rollout restart -n projectcontour deployment/contour deployment/envoy
```

For production, let cert-manager issue and renew them. cert-manager must be installed in the cluster.

```yaml
tls:
  internal:
    provider: cert-manager
    duration: 8760h
    renew_before: 360h
```

See [enabling TLS between Envoy and Contour](https://projectcontour.io/docs/latest/grpc-tls-howto).
